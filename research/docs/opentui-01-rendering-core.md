# Rendering Core

## Purpose
This is opentui's foundation: a terminal renderer driven by a native Zig core, a scene-graph base class every visible widget extends, and a double-buffered cell grid the Zig side actually draws into. Everything else in the framework (widgets, layout, text, input) is built on top of these three pieces.

## Key files
- `packages/core/src/renderer.ts` (4993 lines) — `CliRenderer` class, `createCliRenderer()` factory, `CliRendererConfig`, render-loop/screen-mode/scrollback machinery.
- `packages/core/src/Renderable.ts` — `BaseRenderable`/`Renderable` abstract classes, `RenderableOptions`, `RootRenderable`, Yoga-backed layout properties.
- `packages/core/src/buffer.ts` — `OptimizedBuffer`, the cell-grid drawing surface (char/fg/bg/attribute typed arrays backed by native memory).
- `packages/core/src/renderer-theme-mode.ts` — `RendererThemeMode`, OSC 10/11 terminal background-color polling to infer light/dark theme.
- `packages/core/src/index.ts` — the public package barrel (`@opentui/core`'s actual export surface).

## How it works
`createCliRenderer(config?: CliRendererConfig): Promise<CliRenderer>` is the entry point. It reads `stdout.columns`/`rows` (falling back to `config.width`/`height`, default 80x24), constructs a `CliRenderer`, awaits `renderer.setupTerminal()` (puts stdin in raw mode, sends terminal capability queries), and returns it. `CliRendererConfig` covers: `stdin`/`stdout` streams, `screenMode` (`"alternate-screen" | "main-screen" | "split-footer"`, default alternate-screen), `targetFps`/`maxFps` (default 30/60), `useMouse`/`enableMouseMovement` (default true), `exitOnCtrlC` (default true), `useKittyKeyboard`, `backgroundColor`, and `postProcessFns` (per-frame buffer hooks).

`CliRenderer extends EventEmitter implements RenderContext`. It owns `root: RootRenderable` (the tree's entry point), `nextRenderBuffer`/`currentRenderBuffer: OptimizedBuffer` (double buffering), and drives everything through `lib: RenderLib` — the FFI binding into the native Zig renderer (`lib.createRenderer`, `lib.getNextBuffer`, `lib.writeOut`, etc., from `zig.ts`). Key public methods: `start()`/`stop()`/`pause()`/`resume()`/`auto()` (lifecycle), `requestRender()` (schedule a frame), `resize(width, height)`, `destroy()`, `setBackgroundColor()`, `getStats()`/`getNativeStats()` (frame timing), `focusRenderable()`/`blurRenderable()`, `createScrollbackSurface()` (for split-footer scroll regions), and `getPalette()`/`waitForThemeMode()` for terminal color detection. `CliRenderEvents` enum lists emitted events: `RESIZE`, `FRAME`, `FOCUS`/`BLUR`, `THEME_MODE`, `SELECTION`, etc.

`Renderable` (abstract, extends `BaseRenderable`) is the base every widget subclasses. Constructor takes `(ctx: RenderContext, options: RenderableOptions)`. `RenderableOptions` includes layout props from `LayoutOptions` (flex/margin/padding/position, all Yoga-backed — see doc 02) plus `width`/`height` (`number | "auto" | "N%"`), `zIndex`, `visible`, `buffered` (offscreen `OptimizedBuffer` per node), `live` (opt into the render loop even when idle), `opacity`, and mouse/paste/keydown event callbacks (`onMouseDown`, `onMouseScroll`, `onKeyDown`, etc.). Core methods: `add(child, index?)`, `remove(child)`, `getChildren()`, `updateLayout(deltaTime, renderList)`, `render(buffer, deltaTime)` (subclasses override to draw), `focus()`/`blur()`, `destroy()`/`destroyRecursively()`. `RootRenderable` is the tree root the `CliRenderer` owns; its `calculateLayout()`/`resize()` drive the whole tree's Yoga pass.

`OptimizedBuffer` is the drawable surface: `create(width, height, widthMethod, options)` allocates native memory; drawing methods are `setCell(x,y,char,fg,bg,attributes)`, `drawText(...)`, `fillRect(x,y,w,h,bg)`, `drawBox({...})`, `drawFrameBuffer`/`drawTextBuffer`/`drawEditorView` (composite another buffer or text-buffer view in), plus scissor-rect (`pushScissorRect`/`popScissorRect`) and opacity stack (`pushOpacity`/`popOpacity`) for clipped/composited drawing. Colors are `RGBA` instances (from `./lib/RGBA.js`).

`RendererThemeMode` infers light/dark by sending OSC 10/11 queries and parsing the terminal's reply background color, exposing `themeMode: "light" | "dark" | null` and `waitForThemeMode(timeoutMs)`.

`index.ts` re-exports Renderable, types, buffer, text-buffer(-view), edit-buffer, editor-view, syntax-style, post-processing (effects/filters/matrices), animation Timeline, renderer, plugins, renderables (the whole widget set), zig bindings, console, and `Yoga` as a namespace — this is the full public `@opentui/core` API surface.

## Relevance to our torrent client rebuild
`createCliRenderer()` replaces Textual's `App.run()` bootstrap — one call gives us the terminal session, raw-mode input, and render loop that today's `TorrentApp(App)` gets for free. `CliRenderer`'s `root: RootRenderable` is where we'd mount our top-level layout (equivalent to `TorrentApp.compose()` yielding `Header()`/`DataTable()`/`Footer()`), and every one of our screens (main table view, settings, add-magnet, peers, files) becomes a `Renderable` subtree we `add()`/`remove()` from that root or from a modal container — directly analogous to Textual's `push_screen`/`ModalScreen` pattern in `tui.py`. `CliRenderer.destroy()`/lifecycle events map to the `action_quit` handler that currently calls `manager.save_all_resume_data()`/`save_session_state()`. The `RGBA`/`OptimizedBuffer.drawBox` primitives are the low-level equivalent of the `OPENCODE_THEME` Textual `Theme` and the bordered modal `DEFAULT_CSS` (`border: round $accent`) used throughout `tui.py`'s modal screens — we'd reconstruct that styling via `Box`'s border options (doc 04) rather than CSS strings.
