# Renderables — Input

## Purpose
The interactive/focusable widget set: text entry, dropdown-style selection lists, a numeric slider, and a horizontal tab strip. Together these are opentui's answer to Textual's `Input`, `Select`, `Switch`-adjacent widgets — everything our settings/add-magnet/file-toggle modals need.

## Key files
- `packages/core/src/renderables/Input.ts` (273 lines) — `InputRenderable`: single-line text input, extends `TextareaRenderable`.
- `packages/core/src/renderables/Textarea.ts` (425 lines) — `TextareaRenderable`: multi-line editable text, extends `EditBufferRenderable` (which wraps `EditBuffer`/`EditorView` from doc 03).
- `packages/core/src/renderables/Select.ts` (535 lines) — `SelectRenderable`: scrollable vertical option list with descriptions, keyboard nav, ASCII-font rendering support.
- `packages/core/src/renderables/Slider.ts` (342 lines) — `SliderRenderable`: horizontal/vertical draggable numeric slider with mouse handling.
- `packages/core/src/renderables/TabSelect.ts` (447 lines) — `TabSelectRenderable`: horizontal tab-strip selector (left/right navigation instead of up/down).

## How it works
`InputRenderable extends TextareaRenderable`, forcing single-line behavior: constructor pins `height: 1`, `wrapMode: "none"`, strips `\n`/`\r` from any initial `value`/pasted/inserted text, and rebinds `return`/`kpenter`/`linefeed` to a `"submit"` action instead of newline-insert. `InputRenderableOptions` adds `value`, `minLength`/`maxLength` (default 0/1000), and `placeholder` (string-only, unlike Textarea's StyledText placeholder) on top of `TextareaOptions`. Events (`InputRenderableEvents`): `INPUT` (fires on every keystroke/paste/delete/undo — anything that changes text), `CHANGE` (fires on blur or submit only if the value actually changed since focus — mirrors an HTML `<input>`'s change semantics), `ENTER` (fires on submit, gated by `minLength`). Public surface: `.value` getter/setter, `.maxLength`/`.minLength`, standard `focus()`/`blur()`, and all the inherited Textarea edit methods (`insertText`, `deleteChar(Backward)`, `deleteWord(Backward/Forward)`, `undo`/`redo`) — each override re-emits `INPUT`.

`TextareaRenderable extends EditBufferRenderable` and is the actual keybinding + submit engine: `TextareaOptions extends EditBufferOptions`; `KeyBinding = {name, ctrl?, shift?, alt?, action: TextareaAction}` lets you remap any key to actions like `"submit"`, `"newline"`, `"delete-char-backward"`, etc.; `handleKeyPress(key: KeyEvent): boolean` dispatches through the bound action table; `onSubmit` is a settable callback fired by `submit()`. This is the layer both `Input` and multi-line editors sit on.

`SelectRenderable extends Renderable` (not text-buffer-based — it draws its own list). `SelectOption = {name, description, value?}`. `SelectRenderableOptions` covers `options`, `selectedIndex`, per-state colors (`backgroundColor`/`textColor`/`focusedBackgroundColor`/`focusedTextColor`/`selectedBackgroundColor`/`selectedTextColor`/`descriptionColor`/`selectedDescriptionColor`), `showDescription`/`showScrollIndicator`/`showSelectionIndicator`, `wrapSelection` (wrap-around at list ends), `itemSpacing`, `fastScrollStep`, and `font: keyof typeof fonts` (renders selected/all text via the ASCII-font renderer from doc 07 rather than plain text — a genuinely large-looking select list is possible). Default keybindings: up/k, down/j, shift+up/down for fast-scroll, return/linefeed to select. Methods: `moveUp/moveDown(steps?)`, `selectCurrent()`, `setSelectedIndex(i)`, `getSelectedOption()`. Events: `SELECTION_CHANGED`, `ITEM_SELECTED`.

`SliderRenderable extends Renderable`. `SliderOptions`: `orientation: "vertical"|"horizontal"` (required), `value`/`min`/`max` (default min 0, max 100), `viewPortSize` (thumb-size proxy, defaults to 10% of range), `backgroundColor`/`foregroundColor` (track/thumb colors, sensible grey defaults), `onChange`. `.value` setter clamps to `[min,max]`, fires `onChange` + emits `"change"` event, and calls `requestRender()`. Mouse dragging is wired in the constructor via `setupMouseHandling()`.

`TabSelectRenderable extends Renderable` mirrors `SelectRenderable`'s API shape (`TabSelectOption`, `moveLeft/moveRight` instead of up/down, `selectCurrent`, `setSelectedIndex`, `getSelectedOption`, per-state colors, `showUnderline`, `showScrollArrows`, `wrapSelection`, `tabWidth`) but lays items out horizontally — the natural fit for a top-of-screen mode switcher.

## Relevance to our torrent client rebuild
`InputRenderable` directly replaces every Textual `Input(id=..., value=...)` in `tui.py` — the magnet-URI/file-path prompt in `InputModal`, the numeric fields in `SettingsModal.FIELDS` (download/upload limit, max connections, seed ratio/time), and the two rate fields in `TorrentLimitModal`; its `ENTER`/`CHANGE` events replace the current `on_input_submitted` handler pattern, and `maxLength`/placeholder give us built-in validation-adjacent UX the current code does by hand (e.g. the `InputModal`'s quote-stripping for pasted Windows paths would still be app logic, layered on top via the `INPUT`/`CHANGE` handlers). `SelectRenderable` replaces the two Textual `Select()` dropdowns in `SettingsModal` (`ENCRYPTION_OPTIONS`, `STORAGE_MODE_OPTIONS`) — its `SelectOption.description` field is a bonus we don't currently use (could show e.g. "Forced (encrypted peers only)" as a description under a shorter label). There's no direct `Switch` equivalent in this file set for the `enable_dht` toggle — worth checking `renderables/index.ts`'s other exports (Diff/Markdown/etc., doc 07) or just using a `SelectRenderable` with two options / a `TabSelectRenderable` as the substitute; note this as an open question rather than assuming a Switch renderable exists. `TabSelectRenderable` is a good fit for a possible top-level view switcher (e.g. "Torrents / Settings") if we want to move away from Textual's single-screen-plus-modals model.
