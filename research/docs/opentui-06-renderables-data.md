# Renderables — Data

## Purpose
The widgets for showing structured/scrolling data: a real grid/table renderable with per-cell styled text, and a scrollable viewport container with its own scrollbar. This is the direct target for our torrent list (today's Textual `DataTable`) and for anything (peer list, file list) that can outgrow one screen.

## Key files
- `packages/core/src/renderables/TextTable.ts` (1377 lines) — `TextTableRenderable`: grid layout, per-cell `TextBuffer`/`TextBufferView`, cell/column/grid selection modes, border drawing.
- `packages/core/src/renderables/text-table-width.ts` — `allocateProportionalColumnWidths`: the column-sizing algorithm `TextTable` uses internally.
- `packages/core/src/renderables/ScrollBox.ts` (903 lines) — `ScrollBoxRenderable`: a `BoxRenderable` composing wrapper/viewport/content sub-boxes plus optional vertical/horizontal `ScrollBarRenderable`s, with viewport culling.
- `packages/core/src/renderables/ScrollBar.ts` (423 lines) — `ScrollBarRenderable`: a `Slider`-backed scrollbar with optional up/down (or left/right) arrow buttons and auto-hide visibility.

## How it works
`TextTableRenderable extends Renderable`. Content is a matrix, not row-by-row API: `content: TextTableContent = TextTableCellContent[][]`, where each cell is `TextChunk[] | null | undefined` (`TextChunk` from doc 03's `text-buffer.ts`: `{text, fg?, bg?, attributes?, link?}`) — so cells carry real per-run styling, not just plain strings. Setting `.content = newMatrix` triggers `rebuildCells()`, which allocates one `TextBuffer`+`TextBufferView`+`SyntaxStyle` per cell (`TextTableCellState`). `TextTableOptions` covers `wrapMode`, `columnWidthMode: "content"|"full"`, `columnFitter: "proportional"|"balanced"` (delegates to `allocateProportionalColumnWidths` from `text-table-width.ts`), `cellPadding`/`cellPaddingX`/`cellPaddingY`, `columnGap`, `showBorders`/`border`/`outerBorder` (inner vs. outer border independently controllable), `borderStyle`/`borderColor`/`borderBackgroundColor`, `selectable` with `selectionBg`/`selectionFg`. Selection has three internal modes (`TableSelectionMode = "single-cell"|"column-locked"|"grid"`) resolved from mouse-drag bounds — richer than a typical single-row-cursor table. The table is always `buffered: true` (renders into its own offscreen `OptimizedBuffer` — see doc 01) and uses a Yoga `setMeasureFunc` (doc 02) so its natural size can participate in flex layout like any other box. There is no per-row "add_row"/"update_cell" incremental API (unlike Textual's `DataTable`) — updates go through reassigning `.content` (or presumably mutating specific cells and calling an invalidation method — worth confirming from a live example, not fully certain from static reading alone whether partial-cell updates avoid rebuilding the whole matrix).

`ScrollBoxRenderable extends BoxRenderable`. Internally it builds a small fixed sub-tree: `wrapper` (outer `BoxRenderable`) → `viewport` (`BoxRenderable`, the visible window) → `content` (a private `ContentRenderable extends BoxRenderable` that holds your actual children and implements viewport culling — `_getVisibleChildren()` calls `getObjectsInViewport(viewportRect, childrenSortedByPrimaryAxis, primaryAxis, 0)` so off-screen children are skipped for layout/render, matching Textual's virtualized `DataTable`/`ListView` scrolling model) — plus `horizontalScrollBar`/`verticalScrollBar: ScrollBarRenderable`. `ScrollBoxOptions` layers `rootOptions`/`wrapperOptions`/`viewportOptions`/`contentOptions`/`scrollbarOptions` (each a `BoxOptions` sub-object) on top of the box's own options, plus `scrollX`/`scrollY` (enable each axis), `stickyScroll`/`stickyStart` (auto-stick to an edge — e.g. useful for a live log that should stay pinned to the bottom), `scrollAcceleration` (`LinearScrollAccel`/`MacOSScrollAccel` from `../lib/scroll-acceleration.js`), and `viewportCulling` (default on). Children are added via the normal `add()`/`remove()`/`getChildren()` overrides which delegate to the internal `content` node. Programmatic scroll control: `scrollBy(delta, unit)`, `scrollTo(position)`, `scrollChildIntoView(childId)`, plus keyboard (`handleKeyPress`) and click-and-hold auto-scroll (`startAutoScroll`/`updateAutoScroll`/`stopAutoScroll`).

`ScrollBarRenderable extends Renderable` wraps a `SliderRenderable` (doc 05) as its thumb/track plus two optional `ArrowRenderable` end buttons (`showArrows`). It tracks `scrollSize`/`scrollPosition`/`viewportSize` and auto-hides (`_manualVisibility` flag lets you override the auto-visibility logic via the `visible` setter) when content fits without scrolling — this is what `ScrollBox` instantiates internally for each axis, but it's also usable standalone against any custom scrollable content.

## Relevance to our torrent client rebuild
`TextTableRenderable` is the direct replacement for the main `DataTable(id="table")` in `tui.py` — our six columns (Name, Progress, Down, Up, Peers, State) become one `content` matrix refreshed every second from `refresh_table()`; the `STATE_ICONS` color-coding (today implicit in plain strings) can become real per-cell `fg` in each `TextChunk` (e.g. green for seeding, yellow for checking) since cells carry full styling, something Textual's plain-string cells don't give us as cleanly. The `FileModal`'s file-list `DataTable` (path/size/status columns) and `PeerModal`'s peer-list `DataTable` (address/client/down/up/progress) are both smaller `TextTable`s the same way. Since there's no confirmed lightweight per-cell/per-row incremental update API, our `refresh_table()` loop (which currently does `table.update_cell`/`add_row`/`remove_row` diffing against `seen_keys`) may need to become "rebuild the whole content matrix from `list_handles()` each tick" instead of Textual's finer-grained diffing — a real behavior difference worth validating against an actual running example before committing to it, not just this static read. `ScrollBoxRenderable` is what wraps the table (or the peer/file lists) once torrent counts exceed one screen — it replaces Textual's built-in `DataTable` scrolling, which we get for free there but must compose explicitly here.
