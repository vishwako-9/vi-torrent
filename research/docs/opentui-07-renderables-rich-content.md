# Renderables — Rich Content

## Purpose
The "content authoring" widgets: rendered Markdown, syntax-highlighted code, unified/split diffs, big ASCII-art text, and the line-number gutter that the code/diff renderables share. None of these map 1:1 onto anything a bare torrent client needs, but `ASCIIFont` is directly relevant to the big-logo idea, and `Code`/`LineNumberRenderable` are the reusable substrate `Markdown` and `Diff` are both built on.

## Key files
- `packages/core/src/renderables/Markdown.ts` (2144 lines) — `MarkdownRenderable`: parses GFM markdown (via the `marked` package's `Lexer`) and renders headings/lists/tables/code-blocks as a tree of `Text`/`Code`/`TextTable`/`Box` children.
- `packages/core/src/renderables/markdown-parser.ts` — `parseMarkdownIncremental()`: token-reuse incremental re-parse helper (diffs new content against previous token list, keeps unchanged tokens' object identity, re-lexes only the changed tail) that `Markdown.ts` uses to avoid full re-parses on every keystroke of streamed content.
- `packages/core/src/renderables/Code.ts` (555 lines) — `CodeRenderable`: syntax-highlighted text via tree-sitter (`TreeSitterClient`, `SyntaxStyle`), extends `TextBufferRenderable` (doc 03).
- `packages/core/src/renderables/Diff.ts` (1278 lines) — `DiffRenderable`: unified/split diff view built from a parsed unified-diff string (`parsePatch` from the `diff` package), composing `CodeRenderable` + `LineNumberRenderable` per side with add/remove/context background coloring.
- `packages/core/src/renderables/ASCIIFont.ts` (219 lines) — `ASCIIFontRenderable`: renders text as large block/ASCII-art glyphs into its own `FrameBuffer` (doc 04).
- `packages/core/src/renderables/LineNumberRenderable.ts` (725 lines) — `LineNumberRenderable`/internal `GutterRenderable`: a line-number gutter that tracks any `Renderable & LineInfoProvider` target (doc 02/03), with per-line color overrides and "signs" (e.g. `+`/`-` diff markers) — shared by `Code` and `Diff`.

## How it works
`ASCIIFontRenderable extends FrameBufferRenderable` — the simplest of this group and the one worth knowing in detail. `ASCIIFontOptions`: `text`, `font: ASCIIFontName` (`"tiny"|"block"|"shade"|"slick"|"huge"|"grid"|"pallet"`, from `../lib/ascii.font.js`'s `fonts` map), `color: ColorInput | ColorInput[]` (an array lets each character or gradient stop get a different color), `backgroundColor`, plus selection support (`selectionBg`/`selectionFg`, `selectable`). Construction calls `measureText({text, font})` to size the underlying `FrameBuffer` exactly to the rendered glyph dimensions, then `renderFontToBuffer()` (using `renderFontToFrameBuffer` from the same lib file) draws the glyphs into it. Changing `.text`/`.font`/`.color` re-measures and re-renders. This is a self-contained, ready-made "big text" widget — no need to hand-roll one on a raw `FrameBuffer` as doc 04 speculated.

`CodeRenderable extends TextBufferRenderable`. `CodeOptions` requires a `syntaxStyle: SyntaxStyle` (doc 03/09) and takes `content`, `filetype` (drives tree-sitter grammar selection via `infoStringToFiletype`), `treeSitterClient` (defaults to a shared singleton `getTreeSitterClient()`), `conceal`/`drawUnstyledText`/`streaming` flags, and `onHighlight`/`onChunks` callback hooks to post-process tree-sitter highlights or the resulting `TextChunk[]` before they hit the text buffer.

`MarkdownRenderable extends Renderable` is the largest file: it walks `marked`'s token tree and instantiates a `Text`/`Code`/`TextTable`/`Box` child per block (headings, paragraphs, lists, fenced code blocks, tables — `MarkdownTableOptions` controls table `style: "grid"|"columns"`, width mode, cell padding, borders, reusing `TextTableRenderable` from doc 06 directly). `parseMarkdownIncremental` is what makes it viable for streaming/live-updating markdown (e.g. an LLM response) without full re-lex cost each update.

`DiffRenderable extends Renderable` parses a unified diff string with `parsePatch()`, builds per-line `LogicalLine` records (`type: "context"|"add"|"remove"|"empty"`, optional `sign`/`color`), and renders `unified` or `split` view by composing a `CodeRenderable` (or two, for split) with a `LineNumberRenderable` gutter, using `addedBg`/`removedBg`/`contextBg` (and separate `*ContentBg` variants) plus `addedSignColor`/`removedSignColor` for the classic green/red diff look. `syncScroll` keeps both sides scrolled together in split view.

`LineNumberRenderable`'s internal `GutterRenderable` tracks a target's `LineInfoProvider` interface (`lineInfo`, `lineCount`, `scrollY` — doc 02/03) so the gutter automatically follows the target's scroll position and reflows on line-count changes; `lineColors`/`lineSigns` (per-line-number maps) are how `Diff` paints its +/- gutter markers.

## Relevance to our torrent client rebuild
`ASCIIFontRenderable` is the concrete answer to the "big logo" idea raised earlier — replacing the current plain `Static("⇄ vitorrent  press / for commands")` header line in `tui.py` with an actual large block-letter "VITORRENT" wordmark is a few lines: `new ASCIIFontRenderable(ctx, {text: "VITORRENT", font: "block", color: theme.primary})`, sized automatically, no manual `FrameBuffer` pixel work needed. `Markdown`/`Code`/`Diff` have no obvious use in the torrent client itself (we're not rendering source diffs or markdown documents) — the one plausible future use is if we ever add an in-app "what's new"/changelog viewer or embed a README, at which point `MarkdownRenderable` would be a direct drop-in. `LineNumberRenderable` is likewise not needed for our current feature set (no line-oriented content anywhere in `tui.py`/`session.py`). Net: read this group mainly for `ASCIIFont`; the rest is available but not on our critical path.
