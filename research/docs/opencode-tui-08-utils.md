# Utils

## Purpose
Six standalone utility modules with no Solid/reactive state: OS-clipboard access (including image support and SSH-safe OSC 52 fallback), external `$EDITOR` invocation, mouse-selection-copy glue, a generic debounced-signal helper, terminal-color querying, and session-transcript-to-Markdown formatting.

## Key files
- `util/clipboard.ts` — `Clipboard.read()`/`Clipboard.copy()`: cross-platform (macOS/Linux/Windows) clipboard read/write, text and image, plus an always-on OSC 52 write for SSH sessions.
- `util/editor.ts` — `Editor.open()`: writes a temp file, suspends the renderer, spawns `$VISUAL`/`$EDITOR`, resumes and returns the edited content.
- `util/selection.ts` — `Selection.copy()`: reads the renderer's current mouse-drag text selection and copies it, showing a toast.
- `util/signal.ts` — `createDebouncedSignal()`: a `createSignal` whose setter is debounced (via `@solid-primitives/scheduled`).
- `util/terminal.ts` — `Terminal.colors()`/`getTerminalBackgroundColor()`: OSC 10/11/4 escape-sequence querying for foreground/background/16-color palette.
- `util/transcript.ts` — `formatTranscript()`: renders a session's messages/parts into a Markdown document (used by both "copy transcript" and "export to file").

## How it works
`Clipboard.copy(text)` always does two things: first an unconditional OSC 52 write (`writeOsc52`) — a terminal escape sequence (`\x1b]52;c;<base64>\x07`, wrapped in a `tmux`-passthrough sequence if `$TMUX`/`$STY` is set) that lets the *terminal emulator itself* set the system clipboard, which is what makes copy work transparently over SSH even though the process has no direct clipboard access; then it also calls a platform-specific native copy method (`getCopyMethod()`, memoized via a `lazy()` helper so the platform-detection logic — checking for `osascript`/`wl-copy`/`xclip`/`xsel`/PowerShell — runs only once). On Windows specifically, the copy path spawns `powershell.exe -Command "[Console]::InputEncoding = ...; Set-Clipboard -Value ([Console]::In.ReadToEnd())"` and pipes the text via **stdin**, not as a command-line argument — deliberately avoiding PowerShell string interpolation hazards (`$env:FOO`, `$()`) that would occur if the text were embedded directly in the command string. `Clipboard.read()` is platform-branched for **image** paste specifically: macOS shells out to `osascript` to save clipboard image data to a temp PNG and reads it back as base64; Windows/WSL runs a PowerShell one-liner using `System.Windows.Forms.Clipboard]::GetImage()` piped through a `MemoryStream` to base64; Linux tries `wl-paste`/`xclip` for Wayland/X11; if no image is found on any platform, it falls back to plain-text via the `clipboardy` npm package.

`Editor.open({value, renderer})` is a small but important sequencing dance: bail out entirely if `$VISUAL`/`$EDITOR` isn't set; write `value` to a `tmpdir()/<timestamp>.md` file; call `renderer.suspend()` and clear the current render buffer *before* spawning the editor (so the TUI's own screen doesn't fight the editor's terminal control); `Bun.spawn` the editor with `stdin/stdout/stderr: "inherit"` so it takes over the real terminal; after it exits, read the file back, clear the buffer again, `resume()` and `requestRender()` — and clean up the temp file via a `using`-scoped `defer()` regardless of how the function exits.

`Selection.copy(renderer, toast)` is a 10-line glue function used identically in three places (`app.tsx`'s global mouse handler, `ui/dialog.tsx`'s dialog-provider overlay, and presumably elsewhere): read `renderer.getSelection()?.getSelectedText()`, bail if empty, otherwise copy + show an info toast + `clearSelection()`. Its existence as a standalone util rather than inline code is precisely because it needed to be called from three unrelated places behind an experimental flag (`Flag.OPENCODE_EXPERIMENTAL_DISABLE_COPY_ON_SELECT`).

`createDebouncedSignal(value, ms)` is a two-line wrapper composing `solid-js`'s `createSignal` with `@solid-primitives/scheduled`'s `debounce()` — used exactly once in the codebase (session-list search input) but factored out as a general-purpose primitive.

`Terminal.colors()` sends OSC 11 (background), OSC 10 (foreground), and 16x OSC 4 (palette) queries simultaneously, then parses whichever escape-sequence replies arrive within a 1-second timeout (resolving early if all 16 palette entries arrive first). This is a **different, standalone implementation** of the same OSC-11-background-luminance-to-dark/light-mode logic that's inlined directly in `app.tsx`'s `getTerminalBackgroundColor()` — the two aren't shared, apparently duplicated rather than factored out (worth noting as an inconsistency in their own codebase, not something to imitate).

`formatTranscript()` is pure string-building, no I/O: builds a Markdown document with a title/session-ID/created/updated header, then iterates messages, formatting each as `## User` or `## Assistant (Agent · model · duration)` (metadata optional) followed by its parts — text parts pass through verbatim (unless `synthetic`), reasoning parts are wrapped in `_Thinking:_` (only if `options.thinking`), tool parts render as `**Tool: name**` plus optional fenced-code Input/Output/Error blocks (only if `options.toolDetails`). Used identically by both the clipboard-copy command and the file-export command (doc 03), parameterized by the same three boolean options surfaced in `ui/dialog-export-options.tsx`.

## Relevance to our torrent client rebuild
`util/clipboard.ts` is close to directly portable and solves a real problem we'll hit on Windows: copying a magnet link or file path to the clipboard from inside a raw-mode terminal app needs exactly this platform-branching (PowerShell via stdin, not argv) plus the OSC 52 fallback for when we're run over SSH — copy the Windows branch and the OSC 52 write verbatim, skip the macOS/Linux image-paste branches until/unless we need paste-image support (unlikely for a torrent client, though a magnet-link QR-code paste isn't unthinkable). `util/editor.ts`'s suspend-renderer/spawn/resume dance is the right pattern if we ever want an "open in $EDITOR" escape hatch (e.g. hand-editing a tracker list or `.torrent`-file-derived text). `util/selection.ts` is worth keeping as a standalone util from day one rather than inlining, precisely because — like theirs — we'll likely want mouse-selection-copy available from more than one place (main table, any modal). `util/terminal.ts` vs the duplicated inline logic in `app.tsx` is a cautionary tale, not a pattern to copy: pick one OSC-11-background-detection implementation and reuse it, don't let it drift into two copies. `util/transcript.ts`'s "one formatting function, parameterized by options, called from both copy and export commands" is a clean template if we ever add a "copy torrent info as text" or "export session log" feature.
